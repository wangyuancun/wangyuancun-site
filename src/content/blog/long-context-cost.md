先说一个很多人都有的感觉：Claude Code 越用越贵。

它像一个刚坐进工位的新人：脑子是自己的，但桌上那台电脑、能翻的文件、能敲的命令，都是别人提前给它配好的。你只给一个目标，它自己翻文件、改代码、跑命令。这种能自己决定下一步该干什么的，行话叫 agent。

上午九点打开，下午四点还没关。晚上看一眼用量，一天 18 美元，差不多 130 块。可你真正写进项目的代码，有可能不到三百行。

官方文档给的企业数字不算吓人：九成人一天不到 30 美元，平均每人每个活跃日 13 美元。个人和团队的数字更低，平均每天 6 美元，九成在 12 美元以下。可这个整体数字恰恰掩盖了一件更有意思的事——同样是写代码，有人一天二十美元，有人一天两百美元。差的不是手速，是它被要求「记着」多少东西。

记着多少，本来该是硬盘的事——装下一整部电影占的那点空间，也不过几块钱。可这笔账在 AI 身上反了过来：它记得越多，每回答一次就越贵。贵在哪儿？得先看它到底是怎么「记」的。

## 一、它没有记忆，只有一摞纸

AI 模型不记得你昨天说过什么。

每次回答，它都得把之前的对话重新读一遍。这一摞纸，行话叫 context，中文叫上下文。

AI 不认字，它只认编号。你说的话在它读到之前，先得过一道碎纸机：整段打散，碎片逐个标号。不标号，它就算不了。

这些碎片叫 token。中文里，一个汉字差不多一片；英文一个词，常被拆成两三片。所以容量按片数算：16K，是一篇一万多字的报告；256K，是一本二十万字的书；一百万片，比一部《红楼梦》还要厚。

所以「上下文很长」是什么意思？

就是你每次提问，都往它桌上又摞了一摞纸。它得从头翻到尾，才轮到你最后那句话。

## 二、约七倍

11 月 3 日，Peter Belcak 和另外十一位作者发了一份技术报告，题目就叫《You don't need long context》，你不需要长上下文。

他们租了一种跑模型用的芯片，按小时付钱，一台一小时 3.85 美元，约 28 块。这种芯片叫 H100。然后让模型对着一小摞纸和一大摞纸，各写一百万个 token——同样的活儿，同样的产出，看两边各烧掉多少钱。

实验室给出的结果是Qwen 3 Coder Next 从 16K 到 256K，成本从约 0.21 美元/百万 token 涨到约 1.6 美元，约七倍。另外两个开源模型方向一样，幅度小一些。

同一摞纸，写第 1 万个字和写第 25 万个字，价钱不一样：排得越靠后，越贵。

像送外卖：送到三楼，走三楼；送到顶楼，就得把整栋楼爬一遍。

这种排在后面的 token，论文给它起了个名字，叫 late token，直译就是「排在后面的字」。

这里得说清楚：这些钱是「租显卡自己跑」的生产成本，不是你账单上的价格。

你打开价目表，是另一幅样子。Sonnet 4.6 读一百万个 token 收 3 美元，写一百万个收 15 美元。从这一代开始，大多数模型把一百万个 token 塞进去也是这个价——不管你把它排在第几位，单价都一样。长短混在一起，定一个平均数。

只有 Haiku 5.5 例外，超过十万 token 就涨价。这个例外不是随手定的：它是成本压力透出来的一个口子。

价目表是平的，成本不是。那这约七倍去哪了？三个出口。

一是额度。单价没涨，但账按量算：同样的活，带 256K 进去，光输入就要比 16K 多付一大截。

二是速度。你在那儿干等的那几分钟，也是成本。

三是厂商的毛利。它收的钱不随长度涨，成本却涨了，长上下文用得越多，它赚得越薄。

这三样都不写在价目表上，但你每天都在付。三者各占多少，没有公开的拆分数据，所以说「大半是搬运费」，是就量级而言，不是精确测算。

## 三、贵在搬，不在算

上一章说到，位置越靠后越贵。贵在哪一步？不在算，在搬。

模型读你的纸堆时，会给读过的内容做小抄：哪些词和哪些词有关系。下次写新字，直接看小抄，不用重读。这摞小抄，行话叫 KV cache。

问题是，每写一个字，它都要把小抄从头翻一遍。

纸越厚，小抄越厚，翻得越久。变慢不是它在深思，是在等搬运。像一个刀工很好的厨师，食材却放在仓库最里面，每一刀都要跑一趟。

![图2：贵在搬，不在算](/images/blog/long-context-cost/fig2-cost-not-compute.webp)

论文算下来，同样写一百万个 token，长上下文要花的机器时间和钱，是短上下文的 3.6 到 7 倍。3.6 倍是下限，七倍是上限——上一章那个七倍，说的就是最贵的那一头。

钱之外，还有等待。写的东西一样多，可前面压的纸越多，它就得翻得越久、等得越久。你在自己电脑上跑模型，聊到后半段，一句话要等更久，也是同一个道理。

回到 Claude Code 里，这种搬运你看不见，但能感觉到。会话拖到后半段，它回话明显变慢；改错文件，明明前面说好只动 `auth.ts`，它转头去改了 `config`；你半小时前立的规矩，它像没听过。不是它变笨了，是纸堆太厚，它每次都得从头翻，翻到后面就容易翻丢。

## 四、快满才收

看到这里，正常反应是：那就别让它读那么长的纸堆不就好了嘛。

可它要读多长，不全由你说了算。改一个横跨五个文件的功能，这五个文件它都得看；漏看一个，改出来的东西你未必敢用。

所以问题不是「读不读」，是「读过的那些，能不能先收一收」。这个收的动作叫压缩：把厚厚的纸堆，压成一张摘要。

但是压下去就会冒出另外一个问题，压缩出来的结果会不会把重要的东西弄丢？

前面那篇《You don't need long context》，给出的答案有点反直觉：基本不丢，有时候分数还更高。

既然基本不丢，剩下的问题就是：什么时候收。前面那篇论文实际试过两种。

一种是快满才收：桌子快满了，把做过的步骤写成一张摘要，旧纸扔掉。

另一种是每步都收：每做完一步——改完一个文件、跑一遍测试——就收一次，下一轮只带那一张摘要。

这两种收法，论文在几套现成的测试卷上都比过。具体挑了几组搭配来比：不同模型配不同卷子，做同一套题、比分。这几组横着比下来，分数最高的都是快满才收。

以 Opus 4.5 在修 bug 卷上的表现为例：不压缩 70.0 分，快满才收 74.8 分，每步都收 70.2 分。换成别的模型和卷子，顺序也一样：快满才收最高，每步都收最低。

![图3：两种压缩时机](/images/blog/long-context-cost/fig3-when-to-compress.webp)

为什么？因为快满才收，一次收进去的是完整的一段工作：刚做完的几步都还在眼前，摘出来的东西连得上。

每步都收就不一样：刚写下的结论，下一步就要被重新总结一次。每次总结，都是在上一份摘要上再摘一遍——第一次被压掉的细节，第二次连它存在过都不知道。

像传话游戏：第一棒少听一个字，后面每一棒都从这个缺口往下传，传到最后，已经不是原来那句话了。

那每步都收是不是就不能用了？不是。Opus 4.5 用它，分数跟完全不压缩差不多，换到测终端操作的那套卷子上，还高出 4.6 分。它只是没赢过快满才收。

所以它差的那几分，不是压坏了，是反复重摘磨出来的损耗。损耗可以补。

补法很直接：别让它在脑子里重摘——把当前状态写成一张便签摆在外面，下一轮直接读便签接着干，不再回头总结前文。这个做法，论文叫 SSSM。

不过这几组配对里，保分最好的还是快满才收。便签补上了每步都收的短板，但一次收完的那种完整，它还是比不了。

到这里，说的都是什么时候收。还有另一个变量：一次压多狠。时机决定多久压一次，狠度决定每次压掉多少——两者合起来，决定它手上到底还剩多少能用的东西。

压太狠会掉分。Opus 4.5 把上下文压到 16K/12K 那么小，只剩 68.8 分，比不压缩还低——压得这么狠，该留的东西也被一起压掉了。

所以桌上最后能剩多少能用的纸，就看这两件事。

一是收的时机：不管哪个模型、哪套卷子，快满才收的分数都最高。二是收的力度：压到 16K/12K 那么小，比不压缩还低。前者说明别收得太勤，后者说明别压得太狠。

至于压到多小最合适，论文里只有 16K/12K 这一个数，再细的没给。

## 五、怎么落地

那到底怎么落地？下面五条是我自己的工程习惯，不是论文写的。论文只说哪种收法分数高，没教在 Claude Code 里怎么做。

第一，把进度写在文件里，不留在聊天记录里。

两步，配一次，之后不用管。

先建文件：项目根目录放一个 `STATUS.md`，空白即可。

再在 `CLAUDE.md` 里加两句，直接抄：

每轮开始先读 `STATUS.md`。

每完成一件事，把这几行更新进去：现在到哪、下一步做什么、哪些路走不通。

`CLAUDE.md` 是 Claude Code 每轮都会读的项目说明文件，写在这里的指令它始终看得见，你不用每次重复交代。

写出来的东西长这样：

```
进度：登录页表单已接完，测试未写
下一步：补 login.test.ts，再跑一遍 CI
死路：别用 sessionStorage 存 token，刷新会丢
```

为什么不靠自动压缩代劳：压出来的是摘要，还留在上下文里，下一轮照样被重摘一遍；文件是明文，读进来什么就是什么。

第二，探索交给子任务。

没想清楚的方案，开一个子任务去试。它读多少乱七八糟的东西都行，只把结论带回来。

第三，报错只贴关键行。

第一行说是什么错，最后一个指向你文件的栈帧说去哪改。中间几百行编译器抱怨，扔掉。

第四，要改代码，给位置。

说「改 `auth.ts` 第 42 行那个函数」，别说「你先看看这个文件，再告诉我怎么改」。

第五，看用量，到线就换桌。

Claude Code 里有 `/usage`。任务做完，或者上下文用掉一半，就收尾、写状态、开新会话；看到用量条过 50% 还没收尾，就别再往里塞新任务了。

## 六、收尾

说白了就一句：别让它把「我干到哪了」记在聊天记录里，要记在一张清单上。聊天记录是那摞越翻越厚的纸，清单是桌上那张便签。

人靠清单，不靠重听一整天的录音。

省下来的不只是钱。桌子干净了，它看得清，你也看得清。

现在，打开 Claude Code，敲一次 `/usage`，看看你今天翻了多少页。
