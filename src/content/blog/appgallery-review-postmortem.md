11 月 15 日下午三点四十四分，华为应用市场的审核报告出来了。

全文只有一条问题，没有 crash，没有权限缺失，没有隐私政策不合规。只有一句话：

> 我们关注到您当前提交的应用为简单计时类，与当前应用市场上已有的应用类似，大量同类型内容或功能的应用会造成用户混乱，降低用户的总体体验。

依据是《审核指南》3.7。修改建议写得很客气：「期待您能在交互设计、功能深度等方面进一步完善。」

翻译成人话就是：**你这个品类本来就烂大街了，凭什么再来一个？**

## 第一反应是改文案，但这错了

刚看到报告的时候，我的想法很自然：是不是应用介绍写得不够清楚？是不是一句话简介没把卖点讲出来？于是我开始琢磨怎么把「下班倒计时」这几个字换个更高级的说法。

幸好没这么干。

冷静下来想，这是一条**主观判定**——审核员不是在说「你的按钮点不动」，而是在说「我看不出你和别人有什么区别」。文案属于包装，包装得再漂亮，里面装的还是同一个计时器。审核员打开应用两分钟，看的是功能矩阵，不是你的应用描述写得多巧妙。

改文案是最省力的一条路，也正是最容易白费力气的一条路。

## 怎么破：让差异变成「一眼能看见的东西」

我把 1.0.1 到 1.0.2 当成一次产品重构，而不是一次改版。目标很明确——把「计时」从主角降为配角，换一个审核员打开就能一句话说清的新卖点。

具体做了五件事：

**一，换核心卖点。** 从「下班倒计时」改成「专注的时间会确定性地长成一只猫」。头顶那只橘猫有三档形态，只看累计专注时长，不靠抽卡、不靠运气、不靠充值。奶猫 → 橘猫 → 橘猪，数学上不封顶。一句话就能讲清，而且跟「简单计时类」拉开了距离。

**二，加系统级能力。** 桌面服务卡片上可以直接开始和暂停计时，不用打开应用；点首页的猫能生成一张猫卡，走 Share Kit 发给朋友。这两条是同类应用里少见的硬功能——不是文字描述，是审核员真能点到的东西。

**三，加内容层。** 五幕场景插画（上班、加班、咖啡、周末、发工资）随手切换；一段专注结束，猫可能冒出一句猫言，说完就忘，不存档不上传。这些不解决什么刚需，但让应用有了「被做完」之外的质感。

**四，去掉风险词。** 产品从「橘猫摸鱼钟」改名「橘猫发呆日记」，全站清除「摸鱼」二字。3.7 说的是同质化，但「摸鱼」这个词本身还有价值导向的隐患，没必要留着让人多想。

**五，主动把差异写进自测文件。** 自测报告里直接写清「本次不是换皮，是产品重构」，逐条对比 1.0.1 和 1.0.2 改了什么。审核员每天看一堆包，帮他省时间，就是帮自己省时间。

## 技术上的坑，和这次过审同样重要

产品方向对了，工程上还有几道坎，每一道都能让提交前功尽弃。

**Beta SDK 打的包根本上不了架。** 这是最狠的一个：提交审核时直接弹窗硬拦，提示「使用了 HarmonyOS beta 版本的 API」，弹窗只有一个「确认」按钮。我本机默认那个 DevEco Studio 是 26.0.1 Beta1，打出来的包 `apiReleaseType` 是 Beta；必须换 26.0.0 Release 那套全量重编。现在出包后我会先 `unzip -p x.hap module.json | grep apiReleaseType` 自检一眼，十秒钟的事。

**签名顺序反了就废。** 正确顺序是：签 HAP → 解压未签的 APP → 用已签 HAP 覆盖包内那个 → 重新打包 → 签 APP → 双向 verify。如果直接签 `assembleApp` 的产物，APP 里嵌的还是未签 HAP，用户装不上。

**AGC 里同版本号不能并存。** 换包必须先删旧包，删完「发布版本」会解绑，还得回到版本页重新「去选择」再保存草稿。而且新版本会继承上一版的文案和截图，旧内容得逐项替换——不能只看「页面看起来是新的」。

**隐私政策必须线上和包里一致。** 我用的是自己主站的自定义隐私政策，改完产品名后，包内文案和线上页面要同步更新。上线前用 `curl` 确认线上真的变了，否则容易被判「隐私政策与实际不符」。

从被驳回到重新上架，中间隔了四天。

## 几条能带走的经验

- **驳回只有一条主观判定时，不要只改文案。** 审核员判断的是「这个应用在市场上是否重复」，需要的是一个可见的、能一句话说清的新能力。
- **别猜驳回原因，去读报告。** AGC 消息中心 → 通知详情 → 审核报告链接，正文在独立标签页的 `mainIframeView` iframe 里。报告还会写实测设备和系统版本（这次是 Pura 80 / HarmonyOS 7.0.0 / API 26），自己出包的 target API 别低于它。
- **主观驳回不等于产品不行。** 1.0.1 被说「太普通」，换了个卖点、加了几个真功能就过了。代码基底大半没动，变的是「这个东西到底为什么存在」。
- **流程上的坑比产品更难缠。** Beta SDK、签名顺序、版本并存这三件事，任何一件踩了都能让你在提交环节原地打转，而它们跟你的产品好不好一点关系都没有。

应用现在叫「橘猫发呆日记」，在华为应用市场上架。如果你也在做鸿蒙应用，希望这份记录能让你少走一点弯路。
